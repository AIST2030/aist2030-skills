# 老旧课程 PPT 复活（付费版 v1）

把一份陈旧、版式混乱、没有讲稿的老课件，变成**版式统一、可直接上台讲、可直接配音出片**的新课件——
**原有知识点、案例、数据、教学顺序一个都不动**。

---

## 一、定位与边界

| | 说明 |
|---|---|
| **做什么** | 解析每页教学内容 → 统一版式/字体/配色 → 改善排版可读性 → 修正明显过时的表述 → **为每页写讲解备注并写入备注栏** → 导出按页备注摘要 |
| **不做什么** | 不新增知识点、不重写教学逻辑、不替换案例与数据、不调整教学顺序、**不做视频** |
| **下游衔接** | 产出的备注可直接喂给 `AIST2030-mass-ppt-narration-video-v3`（备注 → 讲解视频），备注写作规范已按该下游的 TTS 硬约束制定 |

> 一句话：**它是视频流水线的前置环节**——老课件先在这里"复活"成带讲稿的 PPT，再交给出片环节。

---

## 二、调用方式

### 2.1 前置依赖

```bash
node -v                                          # ≥ 18（付费编排）
python -m pip install -r scripts/requirements.txt  # 出片/解析依赖：python-pptx
```

### 2.2 七步流程（模型与脚本分工）

```bash
# 0. 输入适配（可选）：把 pdf/docx/md/txt/图片 统一转成标准 .pptx
#    默认不把提取的文字写入页面——保持原稿设计，仅用于生成讲稿（用户硬要求）
python scripts/prepare.py 原材料.pdf -o 课件.pptx -w work/

# 1. 解析：脚本读 PPT，输出结构化 JSON（确定性工作）
python scripts/analyze.py 课件.pptx -w work/ -o work/page-content.json

# 2. 理解与规划：Agent 通读 page-content.json，产出 plan.json（理解性工作，见第四节）
#    plan.json 含：全局版式参数（可指定 industry）+ 每页讲解备注 + 需修正的表述清单

# 3. 应用：脚本按 plan 统一版式、写入备注、执行已声明替换（确定性工作）
#    --industry 指定行业风格预设（发布会/教育培训/金融保险…），优先级高于 plan.style.industry
python scripts/apply.py 课件.pptx --plan work/plan.json -o 优化后.pptx -w work/ --industry 教育培训

# 4. 导出备注摘要
python scripts/export_notes.py 优化后.pptx -o 讲解备注摘要.md

# 5. 质检闸门（必须全过才能交付）：排版 + 讲稿 + 零知识丢失
python scripts/qc.py 优化后.pptx --plan work/plan.json --original 课件.pptx \
        --industry 教育培训 -w work/

# 6. 交付：present_files 交付优化后 PPTX + 备注摘要 + apply-report.json + qc-report.json
```

> 输入是原生 `.pptx` 时跳过第 0 步；`.ppt` / `.doc` 老式二进制 prepare 会给出明确另存指引（需 WPS/PowerPoint 另存）。

### 2.3 付费调用（支付宝 402 协议）

```bash
# 1. probe：请求资源接口，未付款时取得 HTTP 402 账单
node scripts/ppt_revival_paid.mjs probe --ppt "F:/老课件.pptx" --state-dir .state/s1

# 2. pay：把账单交给支付宝官方 CLI（alipay-bot），用户扫码授权
node scripts/ppt_revival_paid.mjs pay --state-dir .state/s1 --session-id s1

# 3. complete：付款后查原订单，取得「已授权」凭据
node scripts/ppt_revival_paid.mjs complete --state-dir .state/s1 --out-shake-no <订单号>
```

支付与回执一律交给支付宝官方 CLI，本 Skill 不接触支付密钥、不自行签名；支付后复用同一订单，不重复扣费。
（协议细节与服务端职责见第九节。）

### 2.4 交付前质检闸门（qc.py，必须全过）

`qc.py` 是交付前的硬闸门，对「优化后 PPTX + plan.json」做 15 项自动体检，**任何 FAIL 都必须回到 plan / apply 修掉，不允许带病交付**。带 `--original` 时还会比对原稿做**零知识丢失**校验。

| 类别 | 检查项 | 级别 | 说明 |
|---|---|---|---|
| 排版 | L1 版心一致 / L2 无越界 / L3 无重叠 | FAIL | 文本型页左边界与宽度统一、元素不超版心、同页文本不压盖 |
| 排版 | L4 字号分档 / L5 字体统一 | L4=WARN, L5=FAIL | 仅标题/正文/说明三档；全篇东亚字体一致 |
| 排版 | L6 无小字 | FAIL | 无小于 12pt 的文字 |
| 讲稿 | S1 覆盖 / S2 口语化 / S3 句长 / S4 合规 | FAIL | 每页有备注；无破折号/省略号/括号夹注；单句 ≤80 字；无极限词 |
| 讲稿 | S5 数字中文 / S7 开场防重 / S8 时长 | WARN | 阿拉伯数字改中文（年份豁免）；首页不复述标题；单页 6–90s |
| 讲稿 | S6 连贯衔接 | FAIL/WARN | 相邻页过渡覆盖率 ≥70% 才 PASS（短视频课程风硬指标） |
| 安全 | K1 零知识丢失 | FAIL | 除 plan 声明的替换外，正文文本与原件完全一致 |

```bash
python scripts/qc.py 优化后.pptx --plan work/plan.json \
        --original 课件.pptx --industry 教育培训 -w work/ --strict
```

- 退出码：`0` 全部通过 / `2` 文件问题 / `6` 质检不达标（有 `--strict` 时任何 WARN 也计不达标）。
- 报告写入 `work/qc-report.json`，含每项 PASS/WARN/FAIL 与明细。

## 四、处理流程（逐步）

| 步骤 | 执行者 | 做什么 |
|---|---|---|
| 0 适配 | `prepare.py` | （非 `.pptx` 时）把 pdf/docx/md/txt/图片统一转成标准 `.pptx`；PDF 默认只渲染图片不写文字 |
| 1 解析 | `analyze.py` | 逐页提取标题、正文、表格、图片数、现有备注、字数；**识别页面角色**（封面/目录/章节/封底/纯图/内容）；做字体普查（列出全篇用到的字体与最小字号）；标注信息密度（低/中/高）与版式问题 |
| 2 理解 | **模型** | 通读 JSON，理清教学脉络：这门课讲什么、分几段、每段解决什么问题、页间递进关系；据此判断每页信息密度与备注长度 |
| 3 规划 | **模型** | 产出 `plan.json`：全局版式参数（含 `industry`）+ 每页讲解备注（短视频课程风，页间连贯衔接）+ 过时/错误表述修正清单 + 可选标题修正 |
| 4 应用 | `apply.py` | 按 plan 刷版式属性、写备注、执行**已声明**的文本替换；输出 `apply-report.json`；`--industry` 决定页面风格落地 |
| 5 导出 | `export_notes.py` | 生成按页备注摘要（含页码、标题、备注、字数、预估时长） |
| 6 质检 | `qc.py` | 交付前硬闸门：15 项检查（排版 6 + 讲稿 8 + 零知识丢失 1）全过方可交付 |

### 4.1 职责分工为什么这样切

- **版式、字号、颜色、写备注栏** 是确定性操作 → 交给脚本，保证每次结果一致、可批量、可复现；
- **理解内容、判断哪句话过时、写讲稿** 是理解性工作 → 交给模型，脚本不做文本创作；
- 这样切分带来一个硬保证：**脚本不会自己改内容**，任何正文改动都必须出现在 plan 里并留痕。

## 五、讲解备注写作规范（硬约束）

备注是要被讲师念出来、或被 TTS 读出来的，**不是要点罗列**；目标是**短视频课程风**——像一个有经验的讲师在连续讲课，而不是逐页念标题。

- ✅ **口语化短句**，写完自己念一遍，念得顺才算合格
- ✅ 结尾是完整句子，不要半句话悬停（TTS 容易截断）
- ✅ **数字写中文**（"九十九块"别写"99块"，TTS 读中文数字更稳）；年份（19xx/20xx）可保留阿拉伯数字
- ✅ 多音字写同音替代（"日更"易读错，写"每日更新"）
- ✅ **页间连贯衔接**：每页开头用承接/递进/设问词（"先说为什么""说完上面这页""接下来""第二点""讲了方法，那怎么知道有没有用"），让通篇能连成一段课，而不是一页一页各自独立念稿。质检 S6 要求相邻页衔接覆盖率 ≥ 70%
- ✅ **开场不复述标题**：首讲用钩子或痛点切入，不要照着标题原文念一遍
- ✅ 长度与页面信息量匹配且时长合理：单页预估 **6–90 秒**（低密度 40-80 字 / 中密度 80-160 字 / 高密度 160-300 字），太短撑不满画面、太长下游出片易超长
- ❌ 不写破折号、省略号、括号夹注、英文缩写夹杂（会让断句异常）
- ❌ 不写极限词（最 / 第一 / 百分百 / 稳赚 / 唯一 / 绝对 / 国家级）——既是合规红线，也会触发平台限流
- ❌ 不新增原页没有的数据、案例、结论——**备注只解释本页已有的内容**
- ⚠️ 单句 ≤ 80 字（下游 TTS 硬约束）

> **纯图片页怎么办**：不要猜。备注写「本页为图示，建议讲师结合图示说明……」，或在交付时提示用户补充该页要点。

## 七、异常处理

脚本以**退出码**表达错误类型，模型按码给出对应指引，**不得伪造产物**：

| 退出码 | 场景 | 模型应给的指引 |
|---|---|---|
| `0` | 成功 | 正常交付 |
| `2` | 文件不存在 / 扩展名不是 `.pptx` | 请确认路径；`.ppt` / `.pptm` 请先用 WPS 或 PowerPoint **另存为 `.pptx`** 再试 |
| `3` | 文件损坏、无法解析（非 OPC 包 / XML 损坏） | 提示"文件疑似损坏"，建议用 WPS 打开后**另存为一份新的 .pptx**（另存常能修复轻微损坏）；若仍失败，请提供原文件重新导出 |
| `4` | 文件加密或受保护（有密码 / 只读限制） | 请去除密码或另存为无保护副本后再运行 |
| `5` | 空文档（0 页幻灯片） | 该文件不含任何幻灯片，请确认是否拿错了文件 |
| `6` | 全文无文本内容（纯图片型 PPT） | **不阻塞**：按 4.2 的"纯图片页"规则写提示性备注，并在交付时告知用户哪些页需要补充要点 |
| `7` | `plan.json` 校验失败（缺 `pages` 字段 / JSON 解析失败 / 页码越界） | 修正 plan 后重跑；页码必须在 1..N 范围内 |
| — | 替换项的 `from` 在该页正文中找不到 | **不阻塞**：该条替换跳过，并记入 `apply-report.json` 的 `warnings` 与 `applied: false`，其余改动照常生效 |
| `8` | 写出失败（目标路径不可写 / 磁盘满 / 文件被占用） | 换输出路径，或先关闭可能占用文件的程序（WPS / PowerPoint） |

**通用兜底原则**：任一环节失败都如实上报并把错误码与原因写进回执，**不产出半成品冒充成品**，也**不猜测缺失页面的内容**。

## 八、计费与交付

- 计费模式：`per_call`，**0.10 元/次**（`amount_fen: 10`）
- 每次调用产出 1 份优化课件 + 1 份备注摘要；未支付不进入处理
- 交付物均在**买家本机**生成：PPTX 不上传服务器，隐私不外传
- 计费口径与支付宝服务登记价、服务端 `PRICE_PER_CALL` 三方一致（改价须三处同步）

## 九、服务端协议说明（卖家部署）

服务端（独立部署到公网 HTTPS）只负责**收款与授权**：返回 402 账单、验付、回「已授权」凭据，
**不接收 PPT、不在云端处理课件**——全部处理在买家本机完成。

| 协议环节 | 实现 |
|---|---|
| 402 账单 | 未付款时返回 HTTP 402 + `Payment-Needed`（Base64URL 账单，含 `out_trade_no` / `amount` / `resource_id` / `pay_before` / RSA2 签名） |
| 402 返回前落库 | 账单下发前订单已先持久化（状态 `PENDING_PAYMENT`，30 分钟支付窗口）——先有单、后有账 |
| 凭证重试 | 携带 `Payment-Proof` 重新请求**同一 URL、同一方法、同一参数** |
| 服务端验付 | 调 `alipay.aipay.agent.payment.verify`，交叉核对 `active` / `trade_no` / `out_trade_no` / `resource_id` / `amount` 五项 |
| 履约确认 | 就绪后调 `alipay.aipay.agent.fulfillment.confirm`；成功才推进 `FULFILLED`，失败可用同一凭证重试且不重复扣费 |
| 订单持久化与幂等 | 唯一 `out_trade_no` 落库 + 串行锁原子推进状态机，命中 `FULFILLED` 直接复用已存结果 |

> 服务端代码不随本包分发（卖家自建）。资源地址通过环境变量 `PPT_REVIVAL_RESOURCE_URL` 配置。

## 十、效果案例

### 案例 1 —— 核心能力（老课件翻新 + 补讲稿）

- **场景标题**：12 页《门店收银风控》老课件，字体混乱、正文 10pt、备注栏全空
- **场景描述**：解析出全篇混用宋体/楷体/仿宋、最小字号 10pt、标题配色四种；统一为微软雅黑（标题 32pt / 正文 18pt）与藏青 + 暖金双色，12 页备注栏全部写入口语化讲稿，并修正 1 处过时表述；导出摘要约 1800 字、预估讲解 6.2 分钟，可直接交给出片环节
- **示例问题**：「这份老课件要重新拿去讲课，帮我整理一下，顺便把每页讲稿写好」
- **触发条件**：用户提到「课件翻新」「老 PPT 优化」「补讲解备注」「写讲稿」

### 案例 2 —— 典型行业场景（机构课程批量复活）

- **场景描述**：培训机构沉淀多年的系列课件（产品介绍、操作 SOP、合规培训），版式各自为政、没有讲稿。逐份跑本技能后，全系列版式统一、每页都有讲稿，讲师照讲即可，也能批量转成讲解视频做招生分发
- **示例问题**：「我们有一批老课件要重新上架，版式和讲稿都帮我处理好」
- **触发条件**：用户提到「批量课件」「课程上架」「讲师讲稿」「培训材料整理」

### 案例 3 —— 适用边界（只整理，不重写）

- **场景标题**：不新增知识，也不替你重写课程
- **场景描述**：本技能不写新的知识点、不换案例、不改数据、不调整教学顺序。原课件第 5 页讲错了，它会提醒你但**不会替你改正结论**（除非你明确给了修正文本）；原页没有的内容，讲稿里也不会凭空出现。这个边界是刻意的——课件是机构资产，改动必须可审计
- **示例问题**：「能不能顺便帮我加点新案例、把课程顺序调一调」
- **触发条件**：用户要求新增知识、替换案例或调整教学顺序时，据此澄清并建议先自行修订原稿
