# PPT 备注转动画解说视频（语音驱动分镜版）

把 PPT 备注区的口播稿，转成**画面内容跟着声音动**的动画解说视频——旁白念到"第二个"，第二张卡片就在那一刻入场；字幕逐词高亮，且**严格单行**。

本技能与"静态翻页版"的根本区别：**时间轴精确到词，画面是代码重绘的，不是 PPT 截图**。

---

| 维度 | 静态翻页版 v2 | **本技能（动画版）** |

| 画面来源 | PPT 截图 + 底部字幕带 | **代码重绘**，元素随旁白逐项入场 |
| 字幕 | 底部黑带逐句 | 屏内**词级卡拉OK**，严格单行 |
| 技术栈 | python-pptx + ffmpeg | **Remotion + React + 本地 Chrome** |

只要"能看、批量出片"，用 v2 更省。

## 二、流水线（8 步）

### Step 0 · 读取 PPT 与页面元素
- 用 `python-pptx` 提取：每页**备注区文本**（= 口播逐字稿）+ 每页所有 shape 的文字。
- 记录 `slide_width / slide_height` 算出比例 —— **成片比例必须与 PPT 一致**（如 PPT 是 720×960 = 3:4，成片就用 1080×1440 等比放大 1.5×，**不是拉伸**）。
- ⚠️ **务必区分"备注区"与"页面图形文字"**：页面上的提示句（如"有其他问题可以评论区留言"）常被误当备注内容，会让忠实度断言失败。备注只取 `slide.notes_slide.notes_text_frame.text`。

### Step 1 · 分句 + 忠实度闸门（硬关卡）
把每页备注拆成若干 TTS 单元，每句建议 **15~40 字**，按标点与语义断开。

**闸门逻辑**（必须有，别省）：
```python
joined = "".join(units_for_page)
assert joined == notes[page], "忠实度失败：分句与备注不一致"
```
不一致时**打印首个差异字符的位置与上下文**，直接定位，别靠肉眼比对（长文本肉眼看不出差一个"点"字）。

> 实战价值：这套断言在真实项目里抓到过 2 处错误——漏掉一个"点"字、把页面提示句误当备注。没有断言就会带着错稿渲染 80 分钟。

### Step 2 · 术语发音优化（解决"AI 读得别扭"）
中英混排是 TTS 的传统弱项。建一张**替换表**，只在**送 TTS 的文本**上替换；`clean`（字幕与对齐基准）仍用原文，**因此不破坏 Step 1 的忠实度**。

```python
PRONUNCIATION = [
    # AI 夹在中文里 → 分开成两个音节，避免吞音或怪调
    (r"(?<=[\u4e00-\u9fff])AI(?=[\u4e00-\u9fff])", " A I "),
    (r"(?<![\u4e00-\u9fffA-Za-z])AI(?=[\u4e00-\u9fff])", "A I"),
    (r"(?<=[\u4e00-\u9fff])AI(?![\u4e00-\u9fffA-Za-z])", "A I"),
    # 字母缩写逐字母读更清晰
    (r"\bMoE\b", "M O E"), (r"\bMCP\b", "M C P"),
    (r"\bPC\b", "P C"), (r"\bGEO\b", "G E O"), (r"\bPDF\b", "P D F"),
    # 数字串
    (r"128K", "128 K"),
]
```

**多音字规避（等长同音替身法）**：edge-tts 只吃纯文本，SSML `phoneme` 注音不可用。中文多音字误读（典型：「调用」被读成 tiáo，正确是 diào）用**词级等长同音替换**解决——替身词与原文逐字等长，因此字符索引与原句 1:1，`clean`/字幕/词边界对齐完全不受影响：

```python
POLYPHONE = {
    "调用": "掉用",   # diào yòng —— edge-tts 常读成 tiáo，必须规避
    "调度": "掉度",   # diào dù —— 同字同险
    "长按": "常按",   # cháng àn —— 防御 zhǎng
}
```

配套要求：`align_words()` 回查词边界时，基准必须是 `norm_clean(clean)`（同样做过同音替换的等长字符串），不能拿原始 `clean` 直接 `find`，否则替身后的词回查不到。**对齐完成后还必须把词文本映射回原文**（`w["w"] = clean[ci : ci+len(bare(w["w"]))]`）——否则字幕会把「长按」显示成「常按」、「调用」显示成「掉用」（替身只许出现在送 TTS 的文本里）。**新增词条前先 assert 等长**，这是整套机制不翻车的前提。

**音色选择经验**：
- 播客/知识类女声 → `zh-CN-XiaoxiaoNeural`（Warm 温暖），配 `rate=+25%`、`pitch=-8Hz` 更利落紧凑。
- 沉稳男讲师 → `zh-CN-YunxiNeural`。
- ⚠️ 男声读 AI 这类英文缩写天生比女声更容易别扭，**"AI 读得怪"多半先换音色就能解决**，再考虑文本替换。

### Step 3 · 生成词级时间轴
每句独立合成 → 处理 → 汇总成 `timeline.json`。四个关键动作：

1. **裁剪首尾静音**：edge-tts 每句自带约 0.2s 首静音、0.9s 尾静音；不裁的话动画会早于语音触发。裁完把**词边界整体平移**。
2. **线性校准**：`k = 实际音频时长 / 末词结束时刻`，把所有词时间按 k 缩放，消除累计漂移。
3. **词按字符索引对齐**（核心）：TTS 的分词粒度不可控（"二十八个"可能是 2 个词也可能是 4 个），**不要用分词做触发匹配**。做法是把每个词去标点后回原句找位置，写入 `ci` 字段。
4. **触发器按 ci 定位**：
```ts
export const trigger = (page, shotIdx, substr): number => {
  const idx = page.shots[shotIdx].clean.indexOf(substr);
  for (const w of shot.words)
    if (w.ci >= 0 && w.ci <= idx && idx < w.ci + w.w.length)
      return shot.start + w.t;   // 该词的绝对时刻
};
```
于是"第二个"这个词在哪一刻被念出来，第 2 张卡片就在那一刻入场。

### Step 4 · 规划分镜（N 页 → M 个模板）
**不要一页写一个组件**。27 页归并成 10 类模板即可覆盖：

| 模板 | 适用页 | 要点 |
|---|---|---|
| Cover | 封面 | 主标题 + 副标题 + 关键数字 |
| Steps | 导读、时间线 | 编号步骤；时间线加 `timeline` 样式 |
| Cards | 2×2 特性/能力卡 | 卡片按讲解节奏依次入场 |
| Stats | 关键数字 | 大数字 + 单位 + 说明 |
| Spec | 技术规格 | 规格条 + 要点列表 |
| Panorama | 全景分布 | 3×3 格子，数字逐个弹出 |
| List | 编号入口列表（1~6 项通用） | 项数决定行高与间距 |
| Safety | 红线/边界 | 带警示配色 |
| Faq | 问答 | Q/A 双色 |
| Table / Quote / Summary / Outro / Detail | 速查表、总结、片尾、详情 | |

**触发设计原则**：每个元素挂一个"语义唯一"的触发词。"第二个"这类序数词最可靠；没有序数词的页面按讲解进度**均匀铺开**（`tHead + 0.8 + i * span`）作为兜底。

### Step 5 · 骨架占位（防布局跳动）
未讲到的卡片/列表项，**渲染成等高的虚线骨架构件**，而不是不渲染。

- 好处一：布局不随语音变化而跳动（不占位的话，后面的卡片会突然上移）。
- 好处二：暗示"后面还有内容"，观众有预期，留存更好。

### Step 6 · 自适应字号（防溢出）
**教训**：标题自适应不能只做"两档切换"（够就 74px、不够就 ×0.84），长标题仍会溢出画布。

正确做法是**按视觉宽度反推字号**：
```ts
const textUnits = (s: string) => {           // 中文 1.0 / 英数 0.56
  let n = 0;
  for (const ch of s) n += /[\x00-\xff]/.test(ch) ? 0.56 : 1;
  return n;
};
// 标题
const size = Math.min(TYPE.title, Math.max(46, Math.floor(900 / textUnits(title))));
// 横幅：还要扣掉 letterSpacing，并给右侧页码留出空间
const size = Math.min(34, Math.max(25, Math.floor(650 / Math.max(1, textUnits(text)))));
```

**横幅避坑**：页脚横幅右侧通常有页码，文字区必须 `paddingRight: 190px` 左右为页码让位，否则长文案会压住"05 / 27"。`letterSpacing` 也要计入宽度，否则会差几像素导致折行。

### Step 7 · 渲染与质检

**渲染**（Remotion 4 + 本机 Chrome headless）：
```bash
node node_modules/@remotion/cli/remotion-cli.js render src/index.ts <CompositionId> \
  "<绝对路径>.mp4" \
  --browser-executable="C:\...\chrome.exe" \
  --concurrency=3 --crf=20 --audio-bitrate=192k --codec=h264
```
- **输出必须用绝对路径**：相对路径会被忽略，产物落到 `remotion/out/CompositionId.png|mp4`。
- 并发 ≤ 3~4（8 核机器），否则抢内存。
- 先渲几个 `still` 单帧做视觉质检，再渲全片（全片动辄 1 小时，别拿全片试错）。

**五道质检闸门**：

| 闸门 | 判据 | 备注 |
|---|---|---|
| 规格 | 分辨率/比例/帧率正确 | 比例必须与 PPT 一致 |
| 时长 | 成片时长与时间轴差 < 0.2s | 差得多说明音频没投全 |
| 响度 | 目标 ±1 LUFS | **必挂项**，见下 |
| 黑屏 | 抽帧各页均有内容 | 抽 6~10 帧覆盖不同模板 |
| 字幕 | 严格单行、无叠字 | 抽最宽的字幕块验证 |

**响度必须后处理**：Remotion 直出恒为约 **-24 LUFS**，必须跑双遍 `loudnorm` 归一化到 **-16 LUFS**（短视频/手机观看标准）。归一化时**只重编码音频流、视频流 copy**，画质零损失。

## 三、字幕严格单行（本技能的核心工艺）

用户对字幕的常见要求是"**严格控制单行、不跳行**"。自动换行会让行数随语音变化，观感很差。四层机制：

| 机制 | 参数 | 作用 |
|---|---|---|
| **视觉宽度单位** | 中文 1.0 / 英数 0.58 | 先算容器能容多少单位：`净宽 / 字号` |
| **宽度上限** | `MAX_UNITS`（如 15，容器容 22.8） | 留足余量，物理上不可能换行 |
| **停顿断句** | `GAP_PREFERRED=0.16s`，回溯 5 词 | TTS 在语义边界停顿最大（实测"灰度\|九月"0.39s，词内仅 0.02s），优先在此断句而非硬切 |
| **孤字合并** | `MIN_UNITS=6`，尾块放宽到 ×1.35 | 尾块太短（"入口""里"）回退并入前块 |
| **互斥渲染** | 任一时刻只渲染一块 | 交叉淡变会导致两块同框**叠字**；必须互斥，且容器 top 恒定 → 绝不跳位 |

```ts
// 互斥：只渲染当前块（最后一个 start <= t 的块）
let idx = 0;
for (let i = 0; i < chunks.length; i++) if (t >= chunks[i].start) idx = i;
const c = chunks[idx];
// 非末块：在下一块开始前就退场，杜绝叠字
const outA = isLast
  ? 1 - easeOutCubic(win(t, c.end + 0.28, c.end + 0.5))
  : 1 - easeOutCubic(win(t, chunks[idx + 1].start - 0.06, chunks[idx + 1].start + 0.04));
```

## 四、避坑清单（都是真实踩过的）

1. **忠实度必须断言**：漏字/多字人眼看不出来，没有断言就会带着错稿渲染一小时。
2. **备注 ≠ 页面文字**：只取 `notes_slide`，别把页面提示句混进来。
3. **标题自适应不能只降一档**：按视觉宽度反推字号，否则长标题溢出画布。
4. **横幅要给页码让位**：`paddingRight` 不够会压住页码；`letterSpacing` 要计入宽度。
5. **`--out` 必须绝对路径**：相对路径被忽略，产物悄悄落到 `out/`。
6. **响度必挂**：Remotion 直出 -24 LUFS，必须 loudnorm 后处理。
7. **静音必须裁**：TTS 每句自带首尾静音，不裁则动画早于语音。
8. **触发用字符索引不用分词**：分词粒度不可控，用 `ci` 字符索引定位才稳。
9. **去 BGM 要彻底**：用户要求"去掉背景音"时，删掉音轨与闪避函数即可，但响度归一化仍要重跑（纯人声的 LUFS 不同）。
10. **WMIC 被拉黑不影响成片**：某些环境会拦截 `wmic`，导致渲染进程退出码异常**但成片已成功写出**——判成功要以产物（文件存在 + 时长正确）为准。
11. **字幕块宽度估算要含 letterSpacing**：否则差几像素就折行。
12. **先渲 still 再渲全片**：全片渲染以小时计，别拿它试错。
13. **JS 的 `\w` 不认中文**（Python 的认）：字幕高亮的 clean 索引映射必须用 unicode 属性转义 `/[\p{L}\p{N}_]/u`，否则纯中文句高亮全灭、含英数的句错位到句尾。
14. **断句阈值要实测校准**：分块优先在词间停顿处切，阈值不是拍脑袋——本机 TTS（Yunyang +25%）语义边界实测下限 0.12s，阈值过高会找不到自然断点而在宽度上限处硬切出悬尾短语（如「…屏面是｜聚合扫码」）。
15. **本机坏代理会劫持 Remotion 内部服务器**：渲染偶发 `Visited http://localhost:3000 but got no response` 时，unset 全部代理环境变量 + `--port` 固定端口即可根治。
16. **只改画布/字幕字段不要重跑 TTS**：音频与词时间不变，直接补丁 timeline.json 的 height/bandHeight/contentHeight/captionFontSize 即可，省一轮配音且时间轴零漂移。

## 六、常见问题

- **元素入场早了/晚了**：检查是否裁了首尾静音；再检查触发词的 `ci` 对齐是否命中。
- **字幕偶尔两行**：检查 `MAX_UNITS` 是否按实际字号与容器净宽算过（`净宽/字号 × 0.7` 是个安全起点）。
- **块切换时闪一下两段字**：用了交叉淡变，改成互斥渲染。
- **长视频渲染太慢**：降低 `--concurrency` 反而更稳（内存瓶颈），或分段渲染后 concat。
- **音色不满意**：先换音色（女声/男声、语速、音调三参数），再考虑发音替换表。
