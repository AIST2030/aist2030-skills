## 本技能自身发布填写（SkillHub）

- **Slug（不可改）**：`skillhub-pay-publish-review`（已符合：仅小写字母、数字、连字符）
- **显示名称**：**SkillHub 发布审查助手**（直观表达「发布前合规审查 + 备料」能力）
- **图标建议**：审核/盾牌风格图标，品牌色建议蓝绿（信任 + 检查），或复用 SkillHub 主色
- **计费模式**：`per_call`（按调用量计费）
- **建议单价**：**0.20 元/次**（20 分）。理由：轻量审查/生成类服务，价位适中利于通过率与转化；可按同类微调
- **版本号**：`1.0.0`
- **变更说明**：首次发布：基于 SkillHub「对外发布 Pay Skill」官方规则实现的发布前合规审查与资料准备 skill，支持检查、改稿、备料全流程

### 案例 1 —— 核心能力（合规检查）
- **场景标题**：一键审查 skill 能否上架 SkillHub
- **场景描述**：把待发布的 skill 目录交给本 skill，自动对照官方规则逐项核对 SKILL.md 字段、文件大小、计费配置，输出通过/警告/不通过清单。
- **示例问题**：「检查我这个 skill 能不能发布到 SkillHub」
- **触发条件**：用户提到「发布到 SkillHub」「Pay Skill 发布前检查」「审查我的 skill」。

### 案例 2 —— 典型行业场景（团队工具商业化）
- **场景标题**：团队把内部 AI 工具打包成付费 skill 上架
- **场景描述**：团队写好一个内部工具 skill，用本 skill 跑发布前检查，补齐缺失的 pricing/capability 字段与模糊描述，并生成 Slug、名称、定价、案例等上架资料，直接进发布页填写。
- **示例问题**：「帮我把这个内部工具 skill 改到能发布，资料也一起准备好」
- **触发条件**：用户要「准备 SkillHub 发布资料」「把 skill 改到能发布」。

### 案例 3 —— 边界 / 进阶说明
- **场景标题**：仅做 SkillHub 发布合规，不替代通用代码审查
- **场景描述**：明确本 skill 只针对 SkillHub「对外发布 Pay Skill」的发布规范（文件结构、SKILL.md 字段、计费、案例），不审查业务逻辑 bug，也不适用于其他平台。避免用户误用。
- **示例问题**：「这个 skill 发布到别的平台也能用这个查吗」
- **触发条件**：用户询问适用边界或跨平台发布时，据此澄清。
