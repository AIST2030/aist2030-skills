## 本技能自身发布填写（SkillHub）

- **Slug（不可改）**：`aist2030-skill-standard`（仅小写字母、数字、连字符）
- **显示名称**：**AIST2030 技能搭建标准**
- **图标建议**：规范/标尺风格图标，品牌色建议蓝绿（标准 + 检查），或复用 AIOPC 主色
- **计费模式**：`per_call`（按调用量计费）
- **建议单价**：**0.20 元/次**（20 分）。理由：轻量规范/生成类服务，价位适中利于通过率与转化；可按同类微调
- **版本号**：`1.0.0`
- **变更说明**：首次发布：AIOPC 技能搭建统一标准总纲（RCTFC 字段规格 + 命名规范 + 内/外门禁 + 防同质化红线），支持给标准与对照验收。

### 案例 1 —— 核心能力（给标准）
- **场景标题**：从零按标准造一个「微博短文」技能
- **场景描述**：用户要在 AI发文 模块新建微博短文技能，本 skill 给出命名（AIST2030-post-weibo-v1）、14 必填字段清单、填空模板与 5 步流水线。
- **示例问题**：「帮我在发文模块新建一个微博短文技能，按咱们的规范来」
- **触发条件**：用户提到「新建 skill」「按标准造一个技能」「搭个 xx 技能」。

### 案例 2 —— 典型行业场景（团队技能治理）
- **场景标题**：团队统一技能规格，避免各写各的
- **场景描述**：团队多人并行产出技能，用本 skill 作为唯一标准总纲统一字段、命名、门禁与防同质化红线，再用 factory.py 自动校验、AIST2030-gov-skill-review-v1 做发布前审查。
- **示例问题**：「我们团队造的 skill 格式乱，给我一份统一标准」
- **触发条件**：用户要「统一技能规范」「团队 skill 标准」「出一份搭建标准文档」。

### 案例 3 —— 边界 / 进阶说明
- **场景标题**：仅给标准/验收，不替代业务逻辑实现
- **场景描述**：本 skill 只负责"按什么规格造、过什么门禁"，不写业务 prompt 的具体行业知识，也不替用户跑 factory.py；它产出的是标准说明 + 验收清单，真正的投产由用户执行或交由 gov-skill-review 审查。
- **示例问题**：「这个标准能直接帮我写完技能内容吗」
- **触发条件**：用户误以为本 skill 会代写业务内容时，据此澄清边界。
