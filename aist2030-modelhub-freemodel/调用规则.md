## 一句话原则

**绝大多数情况用 `model="auto"`。** 它会分析问题类型、赛马挑最快最稳的渠道，首选渠道欠费或限流会自动退到下一家。

只有明确知道自己在干什么（要识图 / 要超长文 / 要固定模型做对比）才点名指定。

最小可用请求：

```json
POST http://127.0.0.1:8787/v1/chat/completions
Content-Type: application/json

{ "model": "auto", "messages": [{ "role": "user", "content": "你好" }] }
```

在 WorkBuddy 里更简单：模型下拉选带「AIST2030免费」前缀的条目即可，地址已配好，不用自己填。

## 四条必读请求规则

### 1. 中文必须用 UTF-8 发送

GBK / Latin-1 发中文，上游模型会「认真回答乱码」，表现为**答非所问、回答跑偏**，很容易被误判成模型坏了。

```python
# ✓ Python：ensure_ascii=False 必须有
raw = json.dumps(body, ensure_ascii=False).encode('utf-8')
```

```bash
# ✗ Git Bash 里不要这样：bash 会按 GBK 发出
curl -d '{"messages":[{"content":"中文"}]}'

# ✓ 要传中文，改用文件
curl --data-binary @payload.json -H "Content-Type: application/json" ...
#   payload.json 用 UTF-8 存
```

```bash
# ✓ 纯英文用 -d 没问题，但记得加 --noproxy（否则本机代理会拦截）
curl -s --noproxy '*' -X POST http://127.0.0.1:8787/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"auto","messages":[{"role":"user","content":"1+1=?"}]}'
```

**自检**：网关检测到疑似乱码时，会在响应里带 `_gateway_warnings` 字段。带了这个字段就是编码错了。

### 2. max_tokens 别设太小

思考型模型会先把预算花在 reasoning 上，max_tokens 给小了正文就一个字都没有（**HTTP 200 但 content 为空**）。

网关已内置「自动放大重试」，调用方不用处理。但自己直连上游（绕开网关）时要注意。

### 3. 要关深度思考就用已配好的模型，别自己传 thinking 参数

各家参数不统一，传错会被静默忽略：

- LongCat 认 `thinking: {"type": "disabled"}`
- 智谱认 `thinking: disabled`

网关的 `extraBody` 已统一管理，调用方**不要自己传**。

### 4. 点死某家上游调试用「渠道id:模型名」

```json
{ "model": "bigmodel:glm-4-flash" }
{ "model": "siliconflow:THUDM/GLM-4-9B-0414" }
```

注意：只有冒号前面是**已知渠道 id** 时才算渠道锁。OpenRouter 的 `nvidia/xxx:free` 这类模型名带冒号，不会被误判。

## 代码示例

### cURL

```bash
curl -s --noproxy '*' -X POST http://127.0.0.1:8787/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"auto","messages":[{"role":"user","content":"用一句话说：1+1等于几"}]}'

# ★ 一定要加 --noproxy '*'，否则本机代理会拦截请求
# ★ 要传中文，改用 --data-binary @payload.json（payload.json 用 UTF-8 存）
```

### Python

```python
import json, urllib.request

body = {'model': 'auto', 'messages': [{'role': 'user', 'content': '用一句话说：1+1等于几'}]}
raw = json.dumps(body, ensure_ascii=False).encode('utf-8')   # ← ensure_ascii=False 必须有
req = urllib.request.Request(
    'http://127.0.0.1:8787/v1/chat/completions',
    data=raw, headers={'Content-Type': 'application/json'})
with urllib.request.urlopen(req, timeout=120) as r:
    d = json.loads(r.read().decode('utf-8'))

print(d['choices'][0]['message']['content'])
if d.get('_gateway_warnings'):
    print('⚠ 编码警告：', d['_gateway_warnings'])
```

### Node.js / fetch

```js
const res = await fetch('http://127.0.0.1:8787/v1/chat/completions', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ model: 'auto', messages: [{ role: 'user', content: '你好' }] }),
});
const d = await res.json();
console.log(d.choices?.[0]?.message?.content);
```

### 看图（多模态）

```json
{
  "model": "glm-4v-flash",
  "messages": [{
    "role": "user",
    "content": [
      { "type": "text", "text": "这张图里有什么？" },
```

- `url` 可以填 https 图片地址，但 **base64 更稳**（外链有时会被拒）

### 批量处理

```python
# 控制并发 4~5 路，别一次开几十条（免费渠道有速率限制）
# 实测 5 路并发稳定，超过会被限流
from concurrent.futures import ThreadPoolExecutor

def run(item):
    return call_gateway({'model': 'THUDM/GLM-4-9B-0414',
                         'messages': [{'role': 'user', 'content': item['q']}]})

with ThreadPoolExecutor(5) as ex:
    results = list(ex.map(run, items))
```

大批量（100+）开工前先跑 `python health_check.py` 确认渠道还活着。

## 报错了怎么办

| 现象 | 通常原因 | 怎么办 |
|---|---|---|
| **502** 全部渠道失败 | 没配 Key 或 Key 失效 | 跑 `health_check.py` 看哪几家可用 |
| **503** | 该渠道熔断冷却中 | 响应体里有中文说明，含恢复时间与替代建议；`auto` 模式不受影响 |
| **429** | 免费额度限流 | OpenRouter 每天 50 次、次日 08:00 重置；智谱/硅基是分钟级限流。等几分钟或换一家 |
| **402** | 上游余额不足 | 该渠道已自动沉底，充值后**无需改配置**，冷却到期自动归队 |
| **400** | 账号状态异常/欠费，或 Key 格式不对 | 智谱 Key 是两段式 `id.secret`，**两段都要填**，只填前半段会全渠道 401 |
| **200 但正文空** | 上游降级 | 网关已自动拦截并重试/换渠道；若直连上游遇到，检查 max_tokens 是否太小或没关深度思考 |
| **回答跑偏答非所问** | 中文被按 GBK 发出 | 检查 `_gateway_warnings`，改用 UTF-8 |

## 规则怎么维护

调用规则的唯一真源是 `usage-rules.json`：

```bash
# 改完直接刷新控制面板即可生效，不用重启网关（面板每次打开都重新拉）
# 网关启动时读一次；改了想立刻让 GET /usage-rules 生效，重启网关
```

- **换模型 / 改推荐** → 只改 `usage-rules.json`
- **加渠道 / 调优先级** → 改 `models.json`

两者刻意分离：模型换血很频繁，规则跟着变；渠道配置相对稳定。
