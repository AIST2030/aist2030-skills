# 发布时段时间线推导（slots）

需求：29 条分布于 8 个高峰时段，每次间隔 ≥15min，规避平台限流。

## 时段配额
| 时段 | 配额 | 该时段内发布时刻 | 末次 | 距下一时段 |
|------|------|------------------|------|------------|
| 08:00 | 3 | 08:00 / 08:15 / 08:30 | 08:30 | →10:00 (90min) ✓ |
| 10:00 | 2 | 10:00 / 10:15 | 10:15 | →12:00 ✓ |
| 12:00 | 3 | 12:00 / 12:15 / 12:30 | 12:30 | →14:00 ✓ |
| 14:00 | 2 | 14:00 / 14:15 | 14:15 | →17:00 ✓ |
| 17:00 | 4 | 17:00 / 17:15 / 17:30 / 17:45 | 17:45 | →19:00 ✓ |
| 19:00 | 5 | 19:00 / 19:15 / 19:30 / 19:45 / 20:00 | 20:00 | →21:00 ✓ |
| 21:00 | 6 | 21:00 / 21:15 / 21:30 / 21:45 / 22:00 / 22:15 | 22:15 | →23:00 ✓ |
| 23:00 | 4 | 23:00 / 23:15 / 23:30 / 23:45 | 23:45 | 当日结束 ✓ |

合计 = 3+2+3+2+4+5+6+4 = **29**。任意相邻两次间隔 = 15min（≥15 ✓）；每个时段最大跨度 = (配额-1)×15min，均不越过下一时段起点 ✓。

## 实现
- `scheduler.build_timeline()` 按上表展开为 29 个绝对时刻（当日日期）。
- `run-day` 对每个时刻：`_sleep_until(t)` 精确等待 → `publish_one()` → 间隔 `interval`（默认 900s=15min）→ 下一点。
- fast 模式（mock 冒烟）：`interval=0.1s` 且不等待绝对时刻，仅验证顺序/去重/状态逻辑。

## 续跑与暂停
- 去重源 = 本地 `state.published`：同日重跑自动跳过已发布，续跑剩余配额。
- 发布异常：`publish_one` 内置 1+2 次尝试，全失败抛 PublishError → `run-day` 置 `paused=true` + 写 `notify.log` + 当日停止，不静默续跑。
