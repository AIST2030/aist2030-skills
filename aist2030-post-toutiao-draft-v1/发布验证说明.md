# AIST2030-post-toutiao-draft-v1.0 · 发布验证说明

## 一、技能定位
实现「今日头条 PC 端草稿箱批量发布」的自动化技能：仅操作草稿箱**已存在**文章，不生成新内容；
按 8 个高峰时段配额（08:00×3 / 10:00×2 / 12:00×3 / 14:00×2 / 17:00×4 / 19:00×5 / 21:00×6 / 23:00×4，共 29 条）
自动分布发布，每次间隔 ≥15 分钟；含去重、只读保护、登录态持久化、异常重试与暂停通知。

## 三、核心逻辑 Mock 冒烟（已通过，不触真站）
mp.toutiao.com 在沙箱可解析且可达，除 mock 冒烟外，还可用 `dry-run` 在沙箱对你授权的 cookie 做只读校准（进入草稿箱、列出候选队列、绝不发布）。mock 冒烟则用 `scripts/mock_server.py` 本地假草稿箱验证脚本逻辑：

| 场景 | 参数 | 预期 | 实测 |
|------|------|------|------|
| 单日全量（成功） | `--fail-first 0` | 发满 29、无重复、`paused=false` | ✅ published=29 |
| 续跑去重 | 复用已有 29 条 state | 仅发剩余 6 条、无重复 | ✅ published=35 |
| 重试恢复 | `--fail-first 2` | 每条第 3 次成功，仍发满 29 | ✅ published=29 |
| 重试耗尽暂停 | `--fail-first 9` | 首条耗尽重试 → `paused=true` + 写 `notify.log` | ✅ paused=True + 通知写入 |

> 结论：选区 / 只读点击 / 结果确认 / 本地去重 / 断点续跑 / 重试 2 次后暂停通知 全部按需求实现。

## 四、边界与待办（需你在本机完成）
- **真实端到端**：mp.toutiao.com 在沙箱可达，但真站登录态/发布仍建议在你本机按「使用说明.md」部署后验证（首批建议小批量试跑）；沙箱可做 `dry-run` 只读校准（需你授权使用 cookie）。
- **DOM 定位适配**：头条草稿箱真实 class 可能变动，`references/selector-map.md` 已给出文本/Aria 优先 + CSS 兜底的定位策略，真站首跑若定位失效按该文档微调即可。
- **登录态有效期**：`auth.json` 过期后由 `login` 刷新；调度器检测到未登录会自动 `paused` 并通知，不会静默错发。
