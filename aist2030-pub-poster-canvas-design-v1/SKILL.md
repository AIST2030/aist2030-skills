# 海报排版与出图工作流

## 适用场景

- 竖版营销海报 / 活动海报 / 扫码引导图，标准画布 **1080×1920（9:16）**，与设计室产物对齐时用 **1600×2848**
- 横版流程图 / 横版信息图 / 路径图，画布 **1920×1080（16:9）**（见「横版流程图」一节）
- 社交平台封面（微信朋友圈封面等），画布 **1080×1080**（见「平台封面」一节）
- **密集文字清单 / 书单 / 知识图谱式竖版海报**，画布 **1080×1440（3:4）**（见「密集文字清单」一节）
  - 同节还有 **「≤12 条 + 手机阅读」的 2 列卡片网格**：条目少时用 2 列换纵向预算放大字号，而不是把 10 条拉成一条长单列
- 环境：Windows + Chrome + Python（Pillow / qrcode / opencv-python-headless）
  - 脚本统一用 `C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe`（已装 cv2 / numpy / PIL / qrcode）

## 先选路：designkit 还是手排？

| | 路径 A：美图设计室 designkit | 路径 B：HTML + Chrome 手排 |
|---|---|---|
| 适合 | 用户丢来一张**成品图**要「优化 / 做 N 版」；要 AI 出视觉创意；当前 App 是「美图设计室」 | 有明确文案与结构；要**像素级可控**；要放二维码并做扫码验收；要反复微调 |
| 产物 | JPG（1600×2848 等），**无可改的源文件** | `.html` 源文件 + PNG 成品，可反复改 |
| 迭代 | 回同一 room 继续对话 | 直接改 HTML 重新截图 |
| 验收 | 目视 + PIL 校尺寸 | 目视 + 高度探针 + 扫码解码（两道硬关卡） |

**当当前 Buddy App 是「美图设计室」时，优先走路径 A**——策略要求优先用本 App 的工具，不要默认手排。用户给的是栅格成品图、又要「优化」时，路径 A 也更贴题。

**⛔ 但有一条红线优先于上面的"优先走 A"：只要海报要放二维码 / 小程序码，且要求「能扫」，一律走路径 B 手排。**

理由（实测）：路径 A 的 AI 是"照着描"二维码而不是"贴图"，同一轮里能一张贴对、另一张贴成横向拉伸 1.8 倍的赝品；而且 AI 版式底部留给二维码的空间通常很局促，码面只能做到 160px 量级。路径 B 用 `<img>` 天然保持正方形，码面可做到 400px+，且有 `.html` 源文件可反复改。

另外：路径 A 是**付费**的（美豆），出现 `recharge_required` 时用户可能直接拒绝充值——此时不要停在"等你充值"，**立刻用路径 B 重做**，手排不消耗任何额度。

### 路径 A 完整命令（Windows / Git Bash）

```bash
export PATH="/usr/bin:/bin:/c/Users/Administrator/AppData/Roaming/npm:$PATH"
designkit auth status --check          # 必须是 connected（远端校验，不能用本地 auth status）
designkit create-room                  # 记下 room_id
designkit chat --room-id "$ROOM" --image-file '<原图>' --prompt '<完整需求>'
designkit history-detail --room-id "$ROOM" --watch   # 前台阻塞，一次吐出 N 个 artifact
designkit download --room-id "$ROOM" --output-dir '<目标目录>'
```

- CLI 入口通常不在 PATH 里，需补 `~/.workbuddy/binaries/node/cli-connector-packages` 与 `AppData/Roaming/npm`；实测版本 1.0.63。
- `--watch` 是前台阻塞长命令，**不要主动 `run_in_background`**；超时被系统自动转后台时要订阅完成通知，不能中途收尾。
- `history_update` 事件里 `artifacts` 非空即立刻交付；`next_action=done` 才结束。
- 出现 `recharge_required` 事件 → 把充值链接给用户，等用户说"已充值"后用事件给的 `action_command` 原样恢复。
- **路径 A 的提示词四要点**：① 逐条列出原文并要求「不增删条款、不改数字」；② 逐版指定视觉方向；③ 指定画幅比例（9:16）；④ 点名去掉水印 + 要求无错字/不溢出/不裁切。

## 流程

### 1. 生成二维码

```python
qr = qrcode.QRCode(error_correction=ERROR_CORRECT_H, box_size=16, border=0)
qr.add_data(URL); qr.make(fit=True)
qr.make_image(fill_color=(15,23,42), back_color=(255,255,255)).convert("RGB").save("assets/qr.png")
```

- `border=0`：静默区交给 CSS 控制，否则二维码自带白边，叠在白卡片上会多出一圈
- 中心可叠 logo / 徽章，H 级容错下覆盖面积 ≤ 20% 安全（实测 7%）
- 中文路径无影响（Pillow 正常），注意用绝对路径

### 2. 每个 HTML 都带高度探针

**先用一条 CSS 掐掉 flex 压缩**（漏掉它会让测高结果永远"正常"，见硬规则 11）：

```css
.poster { display:flex; flex-direction:column; height:2848px; overflow:hidden; }
.poster > * { flex:0 0 auto; }   /* ← 必须。绝对定位的装饰不受影响 */
```

```js
if (location.hash === '#diag') {
  document.title = 'SCROLL=' + document.querySelector('.poster').scrollHeight;
}
```

- 读 `.poster` 的 `scrollHeight`，**不要**累加子元素的 `getBoundingClientRect().bottom`——后者会把绝对定位的装饰（底部波浪、光晕、噪点）算进去，稳定返回一个假的"刚好等于画布高"，把真实溢出掩盖掉。
- 若内容区不是 `.poster` 直接子元素（如外面还套了 `.content`），一并设 `flex:none`。

### 3. 测高 → 定尺寸 → 截图

```bash
# 测真实内容高度
chrome --headless=new --disable-gpu --virtual-time-budget=1500 \
  --dump-dom "file:///路径/x.html#diag" | grep -o "NATURAL=[0-9]*"

# 导出 PNG
chrome --headless=new --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
  --window-size=1080,1920 --screenshot="路径/x.png" "file:///路径/x.html"
```

判据：**1880 ≤ NATURAL ≤ 1919**（略小于画布高度，剩余由 `margin-top:auto` 吸收）

- `> 1920` → 底部被 `overflow:hidden` **静默裁掉** → 缩字号 / 间距 / 图片尺寸
- `< 1880` → 底部发空 → 放大二维码或加大区块间距
- 读数陷阱：绝对定位且 `inset` 带负值的装饰层（如 `inset:-40px` 的噪点层）会让 scrollHeight 虚高，**读数后要扣掉负边距的值**

### 4. 扫码验收（必做）

从**导出的成品 PNG** 上直接解码，而不是只验 `qr.png`：

```python
import cv2, numpy as np

def imread_unicode(path):        # cv2.imread 读不了中文路径，必须走字节流
    return cv2.imdecode(np.fromfile(path, dtype=np.uint8), cv2.IMREAD_COLOR)

def imwrite_unicode(path, img, q=95):   # cv2.imwrite 在中文路径下【静默失败】：不报错也不写文件
    ok, buf = cv2.imencode(".jpg", img, [cv2.IMWRITE_JPEG_QUALITY, q])
    assert ok
    buf.tofile(path)

data, _, _ = cv2.QRCodeDetector().detectAndDecode(imread_unicode(png))
assert data.strip() == EXPECTED_URL
```

整图检测失败时先放大 2 倍（INTER_NEAREST）重试；若仍失败，**优先怀疑静默区不足或装饰干扰，而不是二维码本身有错**。

### 路径 A（AI 生成）的二维码：必须当成"会造假"来防

实测同一轮里设计室给两张图贴了同一个码，结果 **v10 贴的是原图像素（可扫），v11 画的是横向拉伸 1.8 倍的赝品**（302×167，13 种预处理全解不出）。AI 是"照着描"而不是"贴图"，交付前必须从成品图解码。

**三步验收**：
1. 先解码源二维码，记下目标串（作为 EXPECT）。
2. 在成品图上 `detectAndDecode`，失败就裁剪码区 + 多档放大（nearest/cubic ×2~4）+ 多档预处理（灰度/127阈值/Otsu/自适应/CLAHE）重试 —— 全失败即判定为赝品。
3. 量宽高比：**真码的暗像素 bbox 必须接近 1:1**。拿到 1.8、2.0 这种比值，不用解码就能判死。

**要点**：写一份 `verify_qr_scan.py` 放项目里反复用，别每次即兴写脚本（即兴版踩过两个坑：`if pts_list` 对 ndarray 报 truth-value ambiguous；`pts` 形状在 detectAndDecode / detectAndDecodeMulti 之间不一致，一律 `np.asarray(pts,float).reshape(-1,2)`）。

**兜底修复（确定性，不依赖 AI 重生成）**：
1. 定位承载二维码的白色卡片：二值化取亮区 → `connectedComponentsWithStats` → 取最大块。
2. 在卡内量出二维码的暗像素 bbox（逐行统计暗像素 x 跨度，文本行窄而稀疏、码区宽而连续，据此排除下方引导文案）。
3. 量出可用空间（卡顶 → 文案顶），白色矩形覆盖旧码。
4. 真码按**正方形**缩放贴入：`N` 由可用高度决定；静默区 = 图内自带白边 + 与文案的间距，按 `N*码面占比/模块数` 折算模块宽度，确保 ≥ 4 模块。
5. 写盘后**重新解码验收**。


## 硬规则与坑（都实测踩过）

1. **画布尺寸靠计算，不靠目测。** `height:1920px; overflow:hidden` 下内容一超就静默裁切，肉眼几乎看不出来（实测三张同时被裁）。
2. **二维码静默区 ≥ 4 个模块宽。** 白边不够（实测 2.5 模块）成品图直接解不出码。1080 宽画布上白边 **≥ 36px** 才稳。二维码外的描边环、扫角框、光晕也要离码面 ≥ 4 模块，否则干扰识别。
3. **二维码显示尺寸 ≥ 300px**（41 模块 × 8px/模块）。
4. **同一个文件不要并行下发多个编辑。** 并行编辑基于同一份快照会互相覆盖，只有最后一个生效（实测一次丢 8 处改动）。同文件必须串行改，或整文件重写。
5. **`margin-top:auto` 收尾**：给最后一个内容区加上，剩余高度自动吸收，底部永不顶边。
6. **内容贴近画布高度时，优先压缩中间区块**，别砍底部 `padding-bottom`，否则底部顶边很廉价。
7. **文案合规**：不用「免费」「领先 / 最佳 / 唯一」「率先」等承诺性或绝对化用词。用「立即体验」替代「免费体验」。
   **支付 / 收益 / 金融类宣传监管更严**，核心手法是 **承诺 → 功能描述**（保持力度与信息量，只把不能兑现的断言换成可核实的功能）：

   | 原表述 | 问题 | 改后 |
   |---|---|---|
   | 转化率**直接拉满** | 功效断言、承诺效果 | 顾客即扫即付 |
   | **零门槛零操作** | 承诺性表述 | 到账无需手动操作 |
   | 让**每一家店都**… | 绝对化（"都" = 承诺全部） | 让门店经营更省心 |
   | **率先**接入 | 同"最"类，需事实依据 | **已**接入 |

   另外两条红线：**禁贬低同行**（「趁竞争对手还没反应过来」→「支付入口已经打开 —— 先一步接入」）；**禁引用第三方品牌 logo**（授权问题，只用文字标识）。
8. **去掉第三方工具水印**（如「XX AI 生成」），交付图必须干净。
9. **同一产品多版本并存时，验收脚本要按文件名前缀区分预期落地页**，否则会把串码当成通过。命名建议 `v1-xxx` / `v4-xxx2.0`，脚本里维护 `(前缀组, 落地页URL)` 映射表。
10. **换版本 = 换二维码**。HTML 引用 `assets/qr-<版本>.png`，别覆盖旧二维码，否则老海报改稿时会串码。二维码脚本支持传参：`make_qr.py "<链接>" qr-v2.png`。
11. **⚠️ flex 列容器会静默压缩子项——这是最阴的一个坑。** `.poster` 一旦是 `display:flex; flex-direction:column` + 固定高度，内容总高超出画布时 flex 会**按比例压扁所有子项**（而不是溢出），最小最软的那块（如 `padding:8px` 的条纹价格条）被自身的 `overflow:hidden` 裁掉文字。
    症状极具误导性：**被裁的往往是文字上半或中间，看起来像是"被上方元素盖住了"**，会让人去查 `z-index`、`margin`、`clip-path`，全都查不出来。
    修法：`.poster > * { flex:0 0 auto; }`，然后按 `scrollHeight` 超出的具体数值，从 `margin-top` / `padding` / `gap` 里等量减回来。
    注：装饰层是绝对定位，不参与 flex 布局，不受影响。
12. **画布可以是 1600×2848。** 需要与设计室产物（1600×2848）视觉统一时用这个尺寸，字号按 1080 宽的 **1.48 倍**等比放。静默区硬指标随画布等比放大：**1600 宽画布上二维码显示 ≥ 420px，白边 ≥ 52px**。
13. **白卡 padding 要算进静默区。** 公众号二维码原图常自带白边（如 344×344 图内 24px 白边）。总静默区 = 图内白边 + 白卡 padding，按 `码面px / 模块数` 折成模块数，确保 ≥ 4。在 CSS 里写注释标出来，免得后人为了"好看"把 padding 调小。
14. **「纯色块 + 大字标题」的成品图要去文字，别丢给 AI erase。** 实测 AI 会把底色块一起改色、留下白色残影、还顺手改掉画布尺寸（1242×558 → 1248×560）。这类图走用户级 skill `local-image-text-erase` 的本地算法，擦除残留可控到 **0 像素**。
15. **验收小图瑕疵必须用 1:1 裁剪对照，不能看缩略图。** 整体缩放会把 1px 级条纹糊掉，又会把正常纹理放大成"伪影"——两个方向都会误判。同理，发到对话里的预览图也可能带缩放伪影，判断以原始像素的局部裁切为准。
16. **★CSS `background: A, B, C` 里 A 是最上层（和 `z-index` 直觉相反）。** 把不透明的底色渐变写在第一个、纹理写在最后，纹理就被整层盖死、**静默不显示**——图看着是"一片平的深色"，代码里却明明有纹理（视频号边框 10 版白做了很久）。要纹理可见必须**越靠上越先写**：`纹理 > 光晕 > 底色渐变`。验证 30 秒：并排 A/B 两版（`纹理,底色` vs `底色,纹理`）截图看像素，实测 std 93 vs 5.8。
17. **"淡显纹理"要换成可测数字，别停在"很淡"。** 取一块无遮挡的框架带 → 减去 61px 滑动均值（先去趋势，**直接取百分位差会被底色渐变污染**）→ 取 `|残差|` 的 99 分位。`alpha .030` 叠在亮度约 20 的深底 ≈ **7/255**，"看得见但不抢眼"；成套出图做到各版 6.8~7.5 即为强度统一。主题底纹的 SVG opacity 要压到 **0.07~0.17**，否则一旦不再被底色遮挡就会跳成"抢眼的图形"。
18. **"设计稿排满了" ≠ "手机能读"。** 校验字号要用**相对画布宽**换算：1080 宽的图在手机上 ≈ ÷2.77。同画布下书名 28px 缩到手机只有 10.1pt（等于废字）；条目少时先把版式压扁（10 条从单列改 2 列）腾出纵向预算，再把字号抬到 40px（14.4pt）。**排版满与字号够大是两件事，别把"没余地"当成"已经够大"。**
19. **`overflow:hidden` 让溢出和 `ellipsis` 截断都静默发生。** 除自然高探针外必须再加截断计数：遍历目标元素数 `scrollWidth > clientWidth + 1` 的个数。放行条件 = `自然高 ≤ 画布高` **且** `CLIP = 0`。

| | 竖版 1080×1920 | 横版 1920×1080 |
|---|---|---|
| 主要风险 | 内容超高 → 底部**被静默裁切** | 卡片太窄 → 文案**折行断在词中间** |

**三条横版专属规则**：

1. **中文默认任意处折行，长文案要手工 `<br>` 断在标点处**。例如 `沉淀贵州本地商家资源，<br>搭建管道收益`；放任自动折行会断出「…商家资 / 源…」这种丑陋断点。
2. **窄容器里的固定短语加 `white-space:nowrap`**（如起点节点的「新人 / 入场评估」用 `<br>` 分行 + nowrap），否则会被挤成「新人 / 入场评 / 估」三行。
3. **字号按卡宽反推**：卡内可用 308px 时，卡片底部成果文案用 **22px**（24px 会溢出折行），正文级标题 42px，标签芯片 25px。

**配色表达进阶感**：四阶段用递进色（青 `#22d3ee` → 蓝 `#3b82f6` → 紫 `#a78bfa` → 金 `#fbbf24`），卡片顶部 6px 色条 + 同色圆形序号徽章 + 标签芯片同色系半透明底，用 CSS 变量 `--c/--cb/--cg` 按 `.s1~.s4` 切换，一份结构四色复用。

**内容搬迁要忠实**：竖向原文的「✅ 阶段成果」搬到卡片底部（`margin-top:auto` 吸底对齐）；末阶段源文若无成果行，可给一个等价的收束徽章（如 🏆 终局）以保持四卡视觉对称。

## 密集文字清单 / 书单式竖版海报（1080×1440，3:4）

用户说「**4:3 竖版**图文海报」「书单 / 清单 / 50 本经典 / N 条目分区呈现」「便于阅读与传播」时用这套。
画布 **1080×1440**（3:4 竖版，即用户口中的"4:3 竖版"；小红书常见竖图比例）。截图 `--window-size=1080,1440`。

**什么时候走这套**：条目 ≥ 20 条、且每条要带说明文字。这类图**越是内容多越不能交给 AI 生成**——50 个书名 AI 必然写错字、漏行，必须手排。

**版面骨架**（实测 50 条 / 5 分区恰好落在 1440 内）

```
.poster 1080×1440，display:flex;flex-direction:column; padding:42px 56px 26px
  header ≈ 172px：品牌行(13px字距5px) / h1(53px 宋体 金色渐变) / 副标(20px) / 纪要行(13px)
  .secs   flex column, gap:13px
    section ≈ 226px = 分区头(≈50px) + 网格(5×32px = 160px + row-gap)
      分区头：序号(14px 强调色) + 区名(27px 楷体) + 价值维度(13.5px 强调色)
              + AI 落地(11.5px 灰，margin-left:auto 右对齐) + 底边 1px 强调色 + 132px 粗压线
      网格：2 列 × 5 行，grid-auto-flow:column
        条目：序号(11px 金) + 《书名》(17px) + 流派芯片(10.5px) + 智慧句(14px 灰)
  .foot   margin-top:auto 吸底 + 顶部金细线：收束引言(19px 楷体) + 落款
```

**四条关键做法**

1. **多列编号清单必须 `grid-auto-flow:column`。** 配 `grid-template-rows:repeat(5,32px)`，条目才会**列优先**填充（01-05 左列 / 06-10 右列）。用默认行优先会得到 `01 02 / 03 04` 的锯齿编号，读起来别扭。
2. **单行三要素**（`《书名》｜流派芯片｜一句智慧`）比两行（书名一行、智慧一行）更省高度，50 条下这是能否塞进 1440 的决定因素。宽度先按**最长一条**手算：序号+书名+芯片+智慧必须 < 列宽（本例 389 < 468），否则智慧句被 `text-overflow:ellipsis` **静默截断**——缩略图完全看不出来。
3. **分区用 CSS 变量切色，一份结构五色复用**：每个 `<section style="--c:#6fbfa8;--cb:…21;--cg:…52">` 声明强调色与其 13%/32% 透明变体，芯片/序号/区名压线/价值维度全部读 `var(--c)`。**别用 `color-mix()`**（Chrome 版本兼容不确定），直接用 8 位 hex（`#6fbfa821`）做透明度。
4. **字号从"缩小后能否看清"倒推**：手机端 1080 宽约显示 390pt（÷2.77）。智慧句 14px → 5.1pt 偏小但可读；**书目正名别低于 17px**，说明句别低于 13.5px 且颜色不要低于 `#a3aebb`（深底上更暗就一定糊）。余量优先加在**行高和正名字号**上，不要加在空白上。

**⚠️ 固定高度画布上 `scrollHeight` 读不出余量（重要）**

`.poster` 有 `height:1440px` 时，`scrollHeight` **恒返回 1440**（元素自身高度是下限）。于是"探针读数 = 画布高"既可能是"刚好塞满"，也可能是"还剩 66px 空格"，**无法区分**。

```js
// #diag  溢出判定可靠；余量判定无效
document.title = 'NATURAL=' + document.querySelector('.poster').scrollHeight;
// #diag3 真实内容高（必须同时 height:auto + 清 margin-top:auto）
p.style.height = 'auto';
document.querySelector('.foot').style.marginTop = '0px';
document.title = 'H=' + p.offsetHeight;
```

实测同一张图：`#diag` 报 **1440**，`#diag3` 报 **1424**。**溢出用 `scrollHeight`，余量用 `height:auto + offsetHeight`**——漏了这条会把 66px 空白一直留着，然后在下一版想加内容时误判"已经满了"。

**排版气质（沉稳典雅向）**：深墨蓝渐变底（`#0e1620→#141e2c→#0a1017`）+ 鎏金标题（`background-clip:text` 四段金渐变）+ 楷体区名 + 表头细金线 + 四角金饰。**标题用宋体、区名用楷体、正文用雅黑**（Windows 只有 `SimSun`/`KaiTi`/`Microsoft YaHei`，无思源宋体）—— 三种字重分工即产生"层次分明"，不用靠颜色堆。

> 内容侧注意：拿到条目清单先**去重与计数**。实测用户给的"50 本"里有一区重复列了同一本书，实际只有 49 —— 补一本同主题的书补足，并在回复里说明改了什么、为什么。

### 少量条目（≤12 条）+ 手机阅读 → 2 列卡片网格

同源需求「每个分区单独出一张」「要适配手机屏幕阅读」时，别沿用上面的密排结构。条目少到 10 条时，**2 列不是把字压小，而是把纵向预算腾出来放大字号**——这是本节最反直觉也最有用的一条。

**算给用户看的那笔账**（1080 宽 ÷ 2.77 ≈ 390pt，即手机屏宽）：

| | 单列 10 条 | 2 列 5 行 |
|---|---|---|
| 纵向占用 | 1419px（画布 1440，**只剩 21px 余地**） | 1125px（**腾出约 360px**） |
| 书名 | 28px → 手机上 10.1pt | **40px → 14.4pt** |
| 智慧句 | 19px → 手机上 6.9pt（**糊**） | **28px → 10.1pt** |

**单列版满了就再也放不大**——设计稿上 28px 看着挺大，缩到手机屏只有 10pt。2 列把 10 条压成 5 行，省下的高度全部投给字号，书名 +43%、智慧句 +47%。

**骨架**

```
.list{flex:1 1 auto;min-height:0;margin-top:20px;
  display:grid;grid-template-columns:1fr 1fr;grid-template-rows:repeat(5,1fr);
  grid-auto-flow:column;gap:13px 16px}
.bk{position:relative;display:flex;flex-direction:column;justify-content:center;
  padding:18px 22px 19px 24px;border-radius:3px;
  background:linear-gradient(180deg,rgba(255,255,255,.030),rgba(255,255,255,.012));
  border:1px solid rgba(255,255,255,.065);border-left:2px solid var(--cg)}
.h{align-items:baseline}          /* 序号 18px 强调色 + 《书名》40px，同一行 */
.w{margin-top:10px;font-size:28px;line-height:1.3;color:#b8c3ce;white-space:nowrap}
```

**四个要点**

1. **`flex:1 1 auto` + `grid-template-rows:repeat(5,1fr)` 必须同时用。** 只写 `1fr` 行高而不给 `.list` 撑满，5 行自然高只有约 680px，底部会空出 550px；只写 `flex:1` 而不写 `1fr`，卡片会被拉伸但内部留白不均。两者合用 = 行高自动均分剩余高度。
2. **卡片必须 `justify-content:center`**：行高被撑高后，内容顶端对齐会显得"上挤下空"。
3. **编号仍要 `grid-auto-flow:column`**（左列 01-05 / 右列 06-10），否则出现 `01 02 / 03 04` 锯齿。
4. **冗余信息要条件渲染。** 分系列出图时，「儒家系列 → 每本都标「儒家」芯片」纯属占宽。用 `school not in name` 判断，**只在书上流派 ≠ 本系列流派时才渲染芯片**——这样杂家系列的易学/史学/佛家/医道/墨家/笔记、兵家里的「纵横」都保留，其余四张自动变干净。

**探针要加"截断计数"**：条目文案长短不一，`overflow:hidden` 会把溢出和截断都静默吞掉，截图看不出来。在 `#diag3` 基础上加一版：

```js
// #diag4  自然高 + 被 ellipsis 截断的元素数（必须 H<=画布高 且 CLIP=0）
p.style.height = 'auto';
var clipped = 0;
document.querySelectorAll('.w,.t').forEach(function (e) {
  if (e.scrollWidth > e.clientWidth + 1) clipped++;
});
document.title = 'H=' + p.offsetHeight + ' CLIP=' + clipped;
```

**宽度先按最长一条手算**再调字号：本例书名最长 7 字 ×40px ≈ 280px、智慧句最长 13 字 ×28px ≈ 364px，卡片内可用 430px，均有余量。改完文案跑一次 `#diag4` 即可确认。

## 视频号边框模板（剪映画中画叠加）

用户说「做视频号边框 / 视频叠加框 / 剪映模板，中间镂空透视频，顶部留标题、底部放品牌」时用这套。**画布 1080×1920（9:16）**，产物是**中间透明的 PNG**。

> ⚠️ 常见坑：用户自己写的留白常偏小（如"顶 60 / 底 80 / 左右 40"）。底部 80px 会被点赞评论栏压住，左右 40px 在曲面屏会被放大裁掉。**以官方规格换算值为准，并向用户说明差异。**

**两个关键技术（决定成败）**

1. **透明靠"抠色"，不靠浏览器透明通道。** 实测 Chrome headless `--screenshot` 默认把透明区合成到**白底**（`alpha=255`），CSS `mask` 挖了洞也没用。正解：页面用纯品红 `#FF00FF` 铺底 → 中间镂空透出品红 → 截图后用 PIL 把品红精确抠成 `alpha=0`（判据 `R>200 & B>200 & G<80`）。框架区深色不会被误抠，边界 AA 像素因 R/B 不同时 >200 也安全。中间层实测 `centerA=0 / frameA=255` 才算过。
   - **★只抠"强品红"会留一圈抗锯齿紫边。** 窗框圆角/边缘处品红与深色框架的过渡像素（如 `(150,30,140)`）R<200 抠不掉，实测 **347px/张**，贴在透明窗四周很显眼（缩略图看不出，1:1 才见）。判据必须**同时吃掉过渡带**：`((R>200)&(B>200)&(G<80)) | ((R>100)&(B>100)&(min(R,B)-G>45))`。要求"红蓝都明显高于绿"，所以不会误伤主题的青绿/暖色（实测改判据后残留 0px、框架 α 仍 255、振幅与对比度不变）。
2. **镂空用 SVG `fill-rule:evenodd` 蒙版**：`<path fill-rule="evenodd" d="M0 0 H1080 V1920 H0 Z M100 360 H980 V1540 H100 Z"/>`，外框减内框一次成型，纹理在上下/左右底板之间**无缝连续**（比 4 块 div 拼接好，后者接缝处纹理对不上）。`mask-size` 要显式给 `1080px 1920px`。

**踩过的坑**

- **★`background: A, B, C` 里 A 是最上层（与 `z-index` 直觉相反）。** 把不透明底色写在第一个、纹理写在最后 = **纹理被整层盖死且静默不显示**，图看着就是"一片平的深色"，代码里却明明写了纹理。视频号边框 10 版真踩过：底纹（电路/网格/代码/节点/刻度/方块）白做了很久。正确顺序 = **越靠上越先写**：`斜纹理 > 主题底纹 > 光晕 > 底色渐变`。验证只要 30 秒：并排两张，左 `纹理,底色`、右 `底色,纹理`，截图看像素（实测左 std 93 / 右 5.8）。
- **文字/装饰层必须 `z-index` 高于 `.frame`**（如 frame=1、文字=2、角标=3）。`.frame` 是不透明的，文字层没设 z-index 会被整层盖住——现象是「图出来了但一个字都看不到」。
- 背景纹理分层时，`background-size` / `background-repeat` 的**值个数必须和图层数一致**（渐变层 `cover`+`no-repeat`，图案层用其平铺尺寸+`repeat`）；否则图案层拿不到 `repeat`，只平铺一格。
- **★文字预留区遮罩（压底）两端 alpha 都要归 0 —— 一律用「两端软过渡」的压底带"悬"在信息区上。** 只要某条边界没有软过渡，它就是一条看得见的硬边，几块拼起来像**跑道条纹**（三段式定高色带是典型反例）。
  - **「贴边的一端可以硬起」是错的** —— 实测代价很大：顶部遮罩从 `y=0` 硬起会把贴边处的主题纹理一起压暗，高频振幅 **6.8 → 4.0**（纹理几乎看不见），而肉眼只觉得"好像淡了点"。所以**即使贴边也用软过渡**。
  - 做法：`0%(α0) → 12%(全强度) → 76~84%(全强度) → 100%(α0)`；`top` 取信息区上沿前 40~60px，`height` 取到信息区下沿后 40~60px。贵州边框实测：竖版 `top:180 height:290`、横版 `top:190 height:440`，振幅稳定 6.8~7.4。
  - 遮罩 `z-index` 要**低于**文字/装饰层、**高于**框架底色层。若遮罩落在带 mask 的 `.frame` 内部，镂空窗内的那部分会被 mask 自动裁掉，不必额外处理。
- **★`-webkit-background-clip:text` 的块级元素里，子元素带 `transform` 会让字形脱离裁剪坐标系被甩到左上角。** 单字时给元素加 **`display:inline-block`** 可修；但★**多个带 `transform` 的子元素即使 `inline-block` 也会全部塌到元素原点、挤成一坨彩色团**（`getBoundingClientRect()` 仍报正确坐标，verify 四项正确通过、探针查不出，只能 1:1 看图）。最小复现：同页 4 行对比（A 现状 / B 去 `filter` / C 去子元素 `transform` / D `inline-block`）→ A、B 坏，C、D 正常 —— **但那是单子元素**；真正的字标是 6 个字各带 transform，D 仍塌。**终解：彻底弃用 `background-clip:text`，改每字独立 `<span>` + `color:` 逐字纯色**（用 `_mix(A,B,t)` 做 accent↔accent2 按 index 插值，视觉仍是连续色带，彻底绕开裁剪）。
- **★`url()` 别嵌套。** 生成 SVG data-URI 的辅助函数若已返回 `url("data:...")`，CSS 里再写 `background:url("{...}")` 就成了双层嵌套 → **静默失效**（元素占位正确、背景不显示）。
- **★★inline `style="..."`（双引号包裹）里绝不能嵌 `url("data:...")`。** 值里的双引号会**提前闭合 style 属性**，后续内容被当成新属性名 → 元素**静默不渲染**（本次侧边织带 + 窗框徽章整体消失，`verify()` 自检照过、缩略图看不出异常；靠 1:1 亮度剖面才发现该处亮度恒为 31、无任何起伏）。
  - 铁律：SVG 辅助函数一律返回**单引号**形式 `url('data:image/svg+xml,...')`。CSS 块里单双引号都合法，所以统一单引号最安全。
- **★`clip-path: polygon()` 里别用 `calc()`。** 实测 `polygon({n}px 0, calc(100% - {n}px) 0, ...)` 会让**整条 clip-path 被忽略** —— 元素退回矩形，斜切边完全不出现且不报错。固定宽度的元素直接写 px。
- **★"高频振幅"只适合量线状纹样。** 大面积**填充型剪影**（喀斯特峰林用 `fill` 叠层次）天然低频，振幅读数偏低（实测 5.5）但视觉存在感并不弱；反过来**密集平行短线**（苗侗百褶裙）会虚高（10.2，压到 7.5 才与其它版齐）。**别把它当唯一判据，必须配 1:1 看图。**
- **★文字可读性用 WCAG 对比度验收，不要靠目测。** 取文字区 **99 分位最亮像素**（最坏情况）算与白字的对比度，要求 **≥ 7:1（AAA）**。这条把"压底够不够深"变成可回归的数字：贵州边框八张实测 标题 11.2~17.5 / 底部 14.3~19.3（压底 alpha .40~.52 即可轻松达标，不必压到全黑）。
- **★地域/主题元素的抽象必须"可读"，而且只能靠 1:1 裁剪判断。** 反例：喀斯特峰用**等距小尖峰** → 平铺后像心电图；蒸汽用**多条短周期**曲线 → 变成"面条"。正解：峰要**宽底 + 圆顶 + 不对称陡坡**、一屏只放 2 个周期；蒸汽**少而长**（2 条贯穿整块）。这类错误在缩略图上只表现为"像是花纹"，完全看不出问题。

**★定制变形字标（把账号名/品牌名做成"标识"，而不是纯文字）**

需要"把账号名设计进画面"时，**多条手法叠加**才像定制字标（单用任何一条都只是普通文字）。**第三版（贵州本地生活）最终落地写法 = 粗黑显示体（站酷庆科黄油体·内嵌子集字体）+ 逐字纯色变形 + 自由悬浮、彻底去掉绶带/底纹/边框**：

| 手法 | 实现 | 作用 |
|---|---|---|
| ① 粗黑显示体（内嵌） | 开源字体 **站酷庆科黄油体** 子集化后 `base64` 内嵌为 `@font-face:'GZLogo'`（机器无内建粗黑 CJK 显示字体，默认只回退到楷体/雅黑）；字宽 0.77em，故字号较楷体上调（竖 64 / 横 104） | 厚重醒目，与默认黑体拉开层级，且跨机一致 |
| ② 整体拉伸右倾 | 父级 `.cn{transform:scaleY(1.10) skewX(-3deg);transform-origin:50% 78%}` | 动势，粗字体只需轻微倾斜（过歪显松散） |
| ③ 逐字变形 | 每字独立 `<span class="ch">` + 各自 `transform:rotate(-3~3deg) translateY(-3~2px)` | 粗字体小角度更稳，无"颤抖感"，比整词统一变换更"活" |
| ④ 关键字放大 | 首字（或锚字）`scale(1.16)` | 视线第一落点、品牌锚点 |
| ⑤ 逐字纯色配色 | `_mix(A,B,t)` 按 index 线性插值、`color:` 每字独立（**不用 `background-clip:text` 渐变**） | 视觉仍是连续色带，但彻底绕开裁剪塌缩 bug |
| ⑥ 主题圆环徽章 | 字标下一条与地域/行业呼应的 SVG 图形（峰形/鼓楼檐/波纹/茶垄同源） | 把地貌做成字标延伸，四版各异 |

| ⑧ 无底纹无边框·自由悬浮 | `.band` 退化为纯定位容器（无 `clip-path`、无渐变底、无 accent 亮线），字标直接浮在画面上 | 干净、不抢视频主体 |

- **★绝不要用 `background-clip:text` + 多个带 `transform` 的子元素**（见「踩过的坑」）—— 多个子元素会全部塌成一坨，且探针查不出。逐字配色一律用独立 `<span>` + `color:`。

**★外部形状融合（把一张"给定形状"（如 AI 生成的青花瓷/书法字标图）融进已有边框或画布）**

用户丢来一张**已画好的字标/形状图**（多半**白底**），要求"融合到已有图形/场景、避免明显边界或重叠瑕疵"时，**不要直接贴图**（白底会留硬边、把深色氛围洗成灰白板 = 用户口中的"明显边界"）。按四步：

1. **抠出形状本体**：`alpha = clip((1 - min(RGB)/255 - floor)/(1-floor), 0, 1) ** gamma`。白底→α0、深色墨迹→α≈1；`floor`(≈0.10) 压掉微弱底纹，避免带出一层灰雾。
2. **重着色**：深色底上用**浅色**（如青白 `#E9FAF4`）；先在底层画一层**模糊扩张的主题 accent 光晕**，再叠字标本体的柔边 α → 天然光边、无硬边。
3. **按真实比例落位**：先用**行墨量剖面**找内容带（如"贵州本地生活"字符带 y246–534 → 1920×284 → aspect **6.76**），挑**宽高比最接近**的预留区放（竖版字标区 1080×160 = 6.75 → 几乎零形变）。**别硬拉**。
4. **多用素材**：形状里除主字外若还有装饰行（纹样/花边），把它当**低透明度装饰带**（op≈0.44）放在主字下方 → 融合更充分、不像只截一截。

- 脚本：`fuse_qinghua.py`（`extract_band` + `place`）；底版由 `make_blank_base.py` 产出（正则把 `.band` 整块从 HTML 删掉再渲染，得到"字标区已清空"的干净底）。
- 注意：`designkit`（美图设计室 AI）**需充值美豆**才出图；本地 α 融合可免费先把结果做出来。

**淡显斜纹理（用户要"科技质感但不抢眼"时的标准配方）**

需求出现「加一点质感底纹 / 淡显 / 不张扬 / 不要太密集 / 不抢眼」时，用**单层细斜线**，别做十字交叉或双角度叠层——那会立刻变"密集"，直接违背诉求。

```css
/* 118deg 斜线 / 2px 线宽 / 30px 周期(疏) / 白 alpha 仅 .030 */
repeating-linear-gradient(118deg,
  rgba(255,255,255,.030) 0 2px,
  rgba(255,255,255,.012) 2px 3px,
  transparent 3px 30px)
```

**强度要有可测量指标，别只说"很淡"**：取顶部一块无遮挡的框架带 → 减去 61px 滑动均值（**先去掉底色渐变的缓慢趋势**）→ 取 `|残差|` 的 99 分位。直接取百分位差会被渐变污染、量不准。

- 实测 `alpha .030` 叠在亮度约 20 的深色底上 ≈ **7/255**，这是"看得见但不抢眼"的量级，十版做到 6.8~7.5 即算强度统一。
- 主题底纹（电路/网格/代码…）的 SVG opacity 要压到 **0.07~0.17**；早期按 0.15~0.6 写，一旦底色不再遮挡就会跳出来变成"抢眼的图形"而不是"质感"。

**SVG 渲染三处关键（决定成败，复用时别重造轮子）**

1. **圆角裁剪**：用 `<clipPath id="fr"><rect ... rx="16"/></clipPath>` 把所有遮挡层（顶/底/侧）包进 `<g clip-path="url(#fr)">`，否则直角矩形会画在设备圆角框外错位。
2. **多行文字垂直居中**：`text_lines()` 首行 `dy=-((n-1)/2)*lh`，后续行固定 `lh`（相对上一行），不要用每行都相对原点的旧算法（会全叠一行）。
3. **图标用 callable**：glyph 写成 `(X,Y,scale)->list[str]`，在 `frame_svg` 内 `if callable(glyphs): for g in glyphs(X,Y,scale): s.append(g)`。别用 `.format()` 拼 `{X(995):.1f}`（format 不认函数调用，会 `KeyError`）。

## 品牌联合 / 「A × B 正式打通」公告海报（1080×1920）

用户说「A 和 B 打通了 / 合作了 / 正式上线，做张海报」时用这套。画布 **1080×1920（9:16）**，产物三件套 `.html` / `.png` / `.jpg`。

**主视觉用「双卡 + 连接器」表达"打通"**，比纯文字排一排 `A × B` 直观得多：

```
品牌行（21px，字距 .36em）
  ↓ 36px
徽章「重磅利好」（金边胶囊）
  ↓ 62px
[ 省团生活 378×262 ]  ⟷  [ 抖音支付 378×262 ]   ← 双卡 + 中间连接器
  ↓ 62px
————  正 式 打 通  ————                        ← 116px 金色渐变 + 左右渐变金线
  ↓ 66px

  ↓ margin-top:auto（吸收余量）
造势文案 46 / 30px
  ↓ 52px + 上边框
落款 42 / 30px
```

**六个要点**

1. **连接器 = 圆形光晕 + CSS 闪电**。闪电用 `clip-path:polygon(58% 0,0 56%,42% 56%,30% 100%,100% 40%,54% 40%)` 画，渐变直接上 `linear-gradient`——**别用 SVG defs 渐变**（每张图都要重定义 id，很啰嗦）。外圈 `border-radius:50%` + `box-shadow` 做光晕。
2. **双卡等宽 378px**：`378×2 + 连接器 134 = 890 < 可用 952`。左右卡各用一方的品牌色做边框 + 名字渐变（左金 / 右青），视觉上「主角在左」。
3. **「正式打通」+ 左右渐变金线**：`display:flex; gap` + 两侧 `flex:1` 的 `linear-gradient(90deg,transparent,金)`。**字号要留够宽度给线**——120px 时线只剩约 90px（看着像瑕疵），降到 **116px + `gap:40px`** 后线长到约 190px 才协调。
4. **★"余量全堆在一处"是缺陷，不是留白。** 首版 H=1598/1920，322px 全落在卖点下方，看起来像漏排了一半。做法：字号整体放大一档（卡片高 224→262、卡片名 54→56、卖点标题 42→46、说明 26→28、造势 41→46、落款 38→42）+ 间距加大 → **H=1795**，剩下的 125px 交给 `.pitch{margin-top:auto}` 当呼吸区。
   > 判据：`#diag4` 的 `H` 落在 **1780~1860** 最舒服（余量 60~140px）。余量 > 250px 就该放大字号，而不是自我说服"留白也是一种设计"。
5. **配色克制**：深蓝黑底 `#070c14→#0d1622→#060a10` + 一方品牌主色（金 `#E8C27A`）+ 另一方双色（抖音 `#25F4EE` / `#FE2C55`）**仅作点缀、不铺面**。淡显斜纹理直接复用视频号边框配方（118° / 2px / 30px / alpha .030）。
6. **第三方品牌只用文字**，不贴对方 logo（授权问题）。文案改写见硬规则 7。

## 手绘 SVG 雷达图（数据可视化主视觉）

不依赖任何图表库，直接算坐标写静态 SVG，截图稳定、可精确控制。

```
中心 (cx, cy) = (300, 300)；网格半径 r_grid = 170；标签半径 r_label = 215
第 i 个轴的角度：a = -90 + i*60 度（i = 0..5），即从正上方开始顺时针
顶点：x = cx + r*cos(a)，y = cy + r*sin(a)

· 网格：按 r_grid 的 0.25 / 0.5 / 0.75 / 1.0 画 4 层六边形（polygon，fill=none）
· 轴线：cx,cy → r_grid 顶点，stroke 用更浅的灰
· 数据多边形：每轴半径取 r_grid*score/100，各轴独立算，连成 polygon
  填充用线性渐变（opacity .3~.55），描边用品牌主色 stroke-width 4
· 顶点：每轴画一个小圆，方便读图
· 中心：白底圆 + 综合分大字 + 「综合分」小字
· 维度标签：r_label 处，
    i=0 上 → text-anchor=middle；i=1,2 右侧 → start；i=3 下 → middle；i=4,5 左侧 → end
    数值用 <tspan fill="主色" dx="12"> 跟在同一行，别换行写（换行会渲染成多余空格）
```

`viewBox` 要留出标签空间：本例用 `-60 30 720 540`（左侧标签 end 对齐需负坐标，右侧标签 start 对齐需右留白）。容器给 `width:932px; height:auto`，SVG 自适应缩放。

## 从路径 A 回退到路径 B 的做法

当路径 A 的成品不可用（二维码是赝品、版式空间不足、用户拒绝付费）时，**不要在坏图上反复修复，直接手排重做**：

1. 先 `Read` 路径 A 的成品图，**目视读出全部文案与版式层级**（配色、布局、图形元素），记成清单。
2. 用 HTML 重建同款视觉语言，文案逐字照搬（内容红线里的数字、条款一个字都不能动）。
3. 把源二维码作为 `<img>` 原样贴入（`width` / `height` 给相同值保证正方形），白卡 padding 留足静默区。
4. 走完「测高 → 截图 → 成品图解码」三道关卡。

好处：产物从"只有 JPG"变成"有 HTML 源文件"，之后改文案/调色/换二维码都是改一行 CSS 重新截图，不再产生任何费用。
