# 付费 Skill 发布前门禁清单（可勾选）

> 用法：上架前逐项打勾。每条都要给「通过 / 警告 / 不通过」，不通过项必须定位到具体文件 + 字段。
> 平台侧规则以官方更新日志为准：<https://skillpay.alipay.com/changelog>

---

## A. 包体与文件结构

- [ ] `SKILL.md` 位于**根目录**（不是子目录里）
- [ ] 包内总大小 **≤ 10MB**
- [ ] 文件总数 **≤ 200**
- [ ] `references/`、`assets/` 只放必要文件，无构建残留（`__pycache__`、`.bak`、日志、大图）
- [ ] 无密钥、无真实 token、无客户隐私数据残留

## B. frontmatter 字段（对外发布必填 6 项）

- [ ] `name`：技能名，直观可读
- [ ] `description`：首句写成「**输入：… 输出：… 适用边界：…**」三段式
- [ ] `tags`：含中英文检索词
- [ ] `version`：语义化版本（如 `1.0.0`）
- [ ] `capability`：能力标识（一句话说明能干什么）
- [ ] `pricing`：`model: per_call` 或 `free`；`amount_fen: <分>`（如 `20` = 0.20 元/次）

> 内部 14 必填字段另见 `AIST2030-gov-skill-standard-v1`，对外发布需两套都过。

## C. 商品资料（可直接填进上架表单）

- [ ] **Slug**：仅小写字母 / 数字 / 连字符，一旦发布通常不可改
- [ ] **显示名称**：买家一眼看懂能力（不要只写技术词）
- [ ] **图标**：与能力语义匹配（审查→盾牌、生成→画笔、数据→图表）
- [ ] **版本号 + 变更说明**：写清「首次发布」或本次迭代改了什么
- [ ] **一句话简介**：买家视角的收益，不是技术视角的实现
- [ ] **3 个效果案例**：核心能力 / 典型行业场景 / 边界说明（模板见 `assets/case-template.md`）
- [ ] **补充材料**（v0.6 起支持）：截图、示例输入输出、FAQ、使用演示

## D. 计费与资质

- [ ] 已选定计费模式：一次性买断 / 订阅制 / 免费，并写下选择理由
- [ ] 定价合理：轻量生成/审查类建议 **0.20 元/次** 量级，不过高过低（待核实：以平台当期规则为准）
- [ ] 企业认证已通过（用户侧自查，文件无法验证）
- [ ] 商户入驻已完成（按调用量计费需入驻；用户侧自查）
- [ ] **「即刻收」协议签约已完成**（v0.8 起新上传 Skill 需签约才支持网页支付）

## E. 支付与交付链路

- [ ] 主链路可用：Agent 内支付，首次支付即绑钱包 + 付款（v0.7）
- [ ] 扫码后自动确认结果并继续安装，无需用户手动输入「已支付」（v0.7）
- [ ] 兜底可用：Agent 支付失败 → 网页支付继续完成购买（v0.8）
- [ ] 交付口径与模式一致：
  - [ ] 买断制 → 交付完整 Skill（v0.8 起含全部版本下载）
  - [ ] 订阅制 → 云端保护运行，**描述中不承诺交付完整原文**
- [ ] 已集成支付能力的 Skill 可下载压缩包做离线备份（v0.8）

## F. 实跑与验收

- [ ] 核心流程用**真实案例**跑通一遍（不是只做语法检查）
- [ ] 输出结构符合 `format`，下游可直接消费
- [ ] 边界写清楚：明确「不做什么」，避免买家预期错位
- [ ] 至少 1 次他人视角审查（可走 `AIST2030-gov-skill-review-v1`）

## G. 上架后经营（v0.4 / v0.5 / v0.6）

- [ ] 开启多版本管理，下次迭代走版本号而非覆盖上传
- [ ] 维护开发者货架与个人主页（品牌沉淀 + 分发）
- [ ] 商品详情补充材料随版本更新
- [ ] 跟踪用户评价与订单经营数据，反向优化简介与定价
- [ ] 每次平台大版本更新后，回官方日志复核受影响的商品描述与交付口径

---

## 常见卡点速查

| 症状 | 常见原因 | 处理 |
|---|---|---|
| 上传被拒 / 体积超限 | 混入了 `.bak`、日志、大图、缓存目录 | 清理后重打包，压到 10MB 内 |
| 描述被判不合格 | 只写了技术实现，没写「输入 / 输出 / 边界」 | 按三段式重写首句 |
| 定价被质疑 | 明显高于同类轻量服务 | 降到 0.20 元/次量级并写明理由 |
| 买家付不了款 | 未签「即刻收」协议，网页支付不可用 | 完成签约后重开支付 |
| 订阅用户要源码 | 商品描述里承诺了交付原文 | 改为云端保护口径表述 |
| 迭代后老买家拿不到新版 | 没用多版本管理，覆盖了旧包 | 走版本号上传（v0.4） |
